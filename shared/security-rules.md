# 安全规范（security-rules）

> 全部 P0，违反即中止。适用所有仓库（Go/TS/Rust）。

## 1. 凭据与密钥

- 禁止硬编码：密码、API Key、Token、私钥、加密盐一律不入代码与文档。
- 本地配置用不入库文件（`.env*`、`config.local.*`，确认在 .gitignore）或系统环境变量；仓库模板只留键名。
- 示例代码/测试用假凭据（`test-key-xxx`），不复制真实值。
- 发现已泄漏的凭据：立即报告用户并建议轮换，不静默删除了事。

## 2. 注入防护

- **SQL**：一律参数化（ent/预编译语句/`?` 占位）；禁止字符串拼接 SQL（含 ORDER BY/表名字段名拼接——白名单映射）。
- **命令执行**：禁止把用户输入拼进 shell 命令；必须执行时用参数数组形式且白名单校验。
- **XSS**：前端渲染用户内容默认转义；`dangerouslySetInnerHTML`/`v-html` 仅限受控富文本并消毒。
- **路径遍历**：用户提供的文件名/路径必须 normalize 后校验前缀，拒绝 `..` 与绝对路径。

## 3. 认证与授权

- 每个新增端点必须过权限校验（登录态/角色/资源归属），无匿名例外；写操作再验证 CSRF/token。
- 鉴权中间件统一在路由装配层启用，禁止依赖「调用方记得校验」。
- 会话/JWT：过期时间明确、签名算法固定（禁 `none`）、退出与刷新逻辑跟随仓库既有实现。
- 越权测试：冒烟至少含一条「A 用户访问 B 用户资源 → 403/404」用例。

## 4. 输入与输出

- 外部输入（HTTP/消息/文件）在边界校验类型、长度、范围、格式，未验证数据不进入业务层。
- 文件上传：校验扩展名/MIME/大小，存储名服务端生成，禁止保留用户原始文件名直接落盘。
- 响应最小化：不回显敏感字段（密码哈希、内部 ID 视仓库惯例）、错误信息不含堆栈/SQL 细节。

## 5. 数据与日志

- 日志脱敏：手机号/邮箱/token/密钥打码后再记；禁止 `fmt.Printf("%+v", req)` 整包打印含敏感字段的请求。
- 删除数据前写快照日志（表/条件/行数或内容摘要）——业务红线。
- 加密存储敏感字段跟随仓库既有方案，不自造加密。

## 6. 依赖与运行时

- 新增依赖先查公开漏洞（简单：`npm audit` / `cargo audit` / `govulncheck`，装了就跑）。
- Docker/部署配置不暴露调试端口与管理端点到公网；`.env` 不进镜像层。
- 限流/防刷：对外写接口按仓库既有中间件挂上限流，新公开接口默认带基础防护。
