## 背景与目标

任务数量增长后，仅靠列表顺序难以组织视图。本次为任务引入「标签」：用户可给任务打多个彩色标签、按标签筛选列表、管理标签字典。目标是让用户在一屏内完成归类与过滤，不引入新页面层级。

## 验收标准（AC）

> 每条必须可验证；AC 编号一旦发布不可复用。

- [ ] AC-001: 任务详情可为任务添加/移除标签，单任务上限 5 个
- [ ] AC-002: 标签含名称与颜色，颜色从预设 8 色中选取，名称 1-10 字符且同项目内唯一
- [ ] AC-003: 列表页支持按单个标签筛选，筛选条件在刷新后保持（URL query 持久化）
- [ ] AC-004: 标签管理入口可重命名与删除标签；删除标签时自动从所有任务摘除，任务本体不受影响

## 范围

**包含**：
- example_be：标签表与任务-标签关联、标签 CRUD 接口、任务打标接口扩展
- example_fe：标签选择器组件、列表筛选栏、标签管理页

**不包含**：
- 多标签组合筛选（下迭代评估）
- 标签拖拽排序、跨项目标签共享

## 功能需求

### example_be

- 新增 `labels` 表与 `task_labels` 关联表；任务接口返回内嵌标签数组
- 接口：标签 CRUD、任务打标/摘标（见 contract.md）
- 删除标签采用软删除，关联行随删除事务清理

### example_fe

- 任务详情：标签选择器（搜索 + 新建一步完成）
- 列表页：顶部筛选栏展示当前标签，URL query `?label=` 同步
- 标签管理：字典列表 + 重命名/删除（删除需二次确认并提示影响任务数）

## 非功能需求

- 打标操作响应 < 300ms（本地后端）；列表筛选为前端过滤 + 后端查询双通道时保持一致
- 接口鉴权沿用既有中间件，无新增匿名端点
